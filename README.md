# 萌萌权限控制台（astrbot_plugin_user_gateway）

<p align="center">
  <img src="logo.png" alt="萌萌权限控制台" width="180" />
</p>

AstrBot 插件：**按好友 / 按群细粒度管控 LLM 使用权限与 token 额度**，并提供用量统计与可视化控制台。

- 插件展示名：**萌萌权限控制台**
- 支持平台：`aiocqhttp`（好友 / 群列表同步依赖 OneBot 接口）；权限与额度内核不依赖具体平台
- 要求 AstrBot：`>=4.22.0`
- 更新历史见 [CHANGELOG.md](CHANGELOG.md)

## 功能总览

| 模块 | 说明 |
| --- | --- |
| LLM 权限 | 好友专属 > 好友等级 > 群专属 > 群等级 > 全局默认，`继承 / 放行 / 禁止` 三态互斥 |
| 权限分场景 | 好友（及其等级）的权限分**私聊 / 群聊**两个维度：私聊禁用不影响群里使用 |
| 自定义等级 | 好友与群各一套等级，等级可带默认权限（私聊 + 群聊两套）+ 额度模板 + 模型路由，对象可批量归级 |
| 模型路由 | 等级指定「主模型 + 备用模型」；私聊按好友等级、群聊按群等级；主不可用 / 熔断自动走备用 |
| 自助切换模型 | 等级里可打开「允许切换」（**默认关 = 只读**）：用户发 **`/切换模型`** 看到卡片（标出当前使用的那个），回序号即切换、回 `0` 恢复默认；私聊改**他的专属模型**、群聊（仅管理员）改**群的专属模型**，各群互不影响 |
| 模型检测 | 等级里可打开「允许检测」（**默认关**）：用户发 **`/切换模型检测`** 真打一遍本分组的模型，然后把**延迟 / 成功率 / 数据时间**标在切换卡片上。检测由「萌萌模型控制台」执行、结果存在它那边；非管理员有指令冷却，同一模型另有探测冷却 |
| token 限额 | 全局 / 等级 / 对象 / **群成员**四层 + 按日 / 按月 / 累计周期；「最具体的一层生效」；观察模式只记账不拦 |
| 指令权限 | 两个维度：对象 / 等级整体开关 + 每条指令的独立规则；默认放行，可切白名单模式 |
| 群成员级管控 | 群页「成员」抽屉：成员列表（身份 / 群名片 / 本群用量）+ 按成员单独设**权限与额度** / 批量 |
| 用量统计 | 调用次数、token（输入 / 缓存 / 输出）、被拒次数、活跃对象、平均延迟、趋势与榜单 |
| 统计页 | 用量明细（筛选 / 分页 / **CSV 导出**）+ 指令 Top 榜 + LLM 活跃时段热力图 + 操作审计 |
| 最后回复 | bot 在每个好友 / 群里的最后一条消息（时间 + 类型：LLM 回复 / 指令回复 / 普通消息） |
| 头像 | 后端抓取并缓存（好友 + 群），离线可用，支持一键「更新头像」 |
| 好友 / 群列表 | 头像、QQ 号、昵称（备注优先），支持搜索 / 排序 / 批量操作 |
| 备份与迁移 | 导出 / 导入**规则**（权限 · 等级 · 归级 · 额度）；合并或覆盖两种模式 |

## 安装

1. 在 AstrBot 后台「插件市场」搜索 **萌萌权限控制台** 安装；或「插件市场 → 本地插件 → 从文件安装」上传发布包 zip；
2. `aiosqlite` 依赖会随插件自动安装；
3. 安装后数据落在 `data/plugin_data/astrbot_plugin_user_gateway/user_gateway.db`（SQLite，自动建表）。

装好后在 AstrBot 后台的「插件页面」打开**权限控制台**即可使用。

## 使用指南

### 1. 先做一次同步

打开控制台后点「同步好友 / 群」，把协议端的联系人列表拉进本地缓存——后面所有页面都基于这份缓存。

### 2. LLM 权限：谁能用 AI

- 在**私聊 / 群聊**页，每个对象都有「LLM 权限」三态开关：
  **继承**（不单独设，看更上层）/ **放行** / **禁止**；
- 权限是**分场景**的：好友的私聊与群聊是两个独立开关（列表顶部切换场景），
  可以做到「私聊禁用、群里照用」；
- 生效优先级（命中最具体的一层即止，管理员默认豁免）：

  ```
  私聊：好友专属（私聊）→ 好友专属（通用）→ 好友等级（私聊）→ 全局默认
  群聊：群成员专属 → 好友专属（群聊）→ 好友专属（通用）
        → 群专属 → 群等级 → 全局默认
        （好友等级只在给该好友显式配了「群聊等级」时才插进这条链）
  ```

- **群聊里默认不看好友等级**：好友的等级只管私聊；群聊里他就是普通群员，
  走群的档位（群专属 / 群等级 / 全局）。想让他在群里按某一档算（比如「群 VIP」），
  在「私聊」页的「群聊等级」列或详情抽屉里，从**群聊等级**里挑一个显式配置。
- **群成员专属**（范围最窄、优先级最高，只影响那个群）：
  「群聊」页每行的「成员」按钮 → 单独给某个人放行 / 禁止，
  典型用法「整群禁止，只给某个人放行」。

### 3. 等级与额度：用量怎么管

- 「限额」页可以建**自定义等级**，分两套（建的时候按钮就分开）：
  **好友等级**管好友的私聊，**群聊等级**管群的归级、以及好友在群里的归级；
  两套的 id 全局唯一，所以「私聊等级」下拉只列好友等级、
  「群聊等级」下拉只列群聊等级，不会互相混（省得配了却不生效）；
  每个等级可配默认权限（好友等级另有一套「群里也生效」的值）、额度模板、专用模型、
  以及「是否允许用户自助切换模型」（默认关 = 只读）；
- 额度四层：**全局默认 → 等级模板 → 对象专属 → 群成员（他在这个群的用量）**，
  同样是「命中最具体的一层即止」，所以「VIP 等级 50 万」不会被「全局 5 万」反手拦掉；
- 周期：按日 / 按月 / 累计，三者可同时生效，任一超限即拦；
- **填 0 = 明确「不限」**（占住档位），留空 / 删除 = 不配置（继续看更粗的层）；
- 等级额度是**每人一份**，不是整组合计；
- 新部署建议先用 **观察模式**（只记账不拦截）跑一周，看看大家的真实用量再切拦截。

### 4. 指令权限：谁能用哪些指令

两个维度、都是三态（继承 / 放行 / 禁止）：

| 维度 | 配在哪 | 回答的问题 |
| --- | --- | --- |
| 对象 / 等级整体开关 | 私聊 / 群聊页的「指令权限」列；等级管理的「默认指令权限」 | 这个人 / 这个群 / 这一等级**能不能用指令** |
| 单条指令规则 | 「指令」页（每条指令一份规则） | **这一条指令**能不能用 |

判定顺序固定：先看「对象能不能用指令」（等级=禁止就是整档人用不了任何指令），
再看「这条指令有没有单独规则」，都没有则用配置里的「指令默认策略」。

- **整档禁止 + 个别人白名单**：把等级 / 群设为禁止，再在私聊 / 群聊页给某个人设「放行」；
- 「指令」页的**对象体检**：选一个好友 / 群 / 成员 / 等级，一屏列出它对每条指令的
  结论（可以用 / 被拦下）与结论来源，还能就地改例外规则。

### 5. 模型路由：不同等级用不同模型

- 等级里可指定**主模型 + 备用模型**（一项 = 一个「供应商 · 模型」）；
- 私聊按好友等级、**群聊按群等级**（不按发言人，避免同群上下文串味）；
- 主模型不可用（未加载 / 连续失败触发熔断）→ 自动走备用，到点自动恢复；
- 下拉里只列已加载的提供商，并标注「当前默认」与「熔断中」。

### 6. 自助切换模型：/切换模型

在「限额 → 等级管理」给某个等级打开**「允许切换模型」**（**默认关**），属于该等级的用户就能自己换模型：

```
用户：/切换模型
bot ：（一张卡片：主题色渐变头部 + 白底候选列表 + 浅色脚注）
      ┌ 模型切换 ─────────────────────────────┐
      │ OpenAI · gpt-4o-2024-11-20-preview-very- │  ← 当前模型在标题区，长名字折行不截断
      │ long-name                                │
      │ VIP（好友等级）· 今日 12.3K tokens · 8 次  │
      ├──────────────────────────────────────────┤
      │ 1  OpenAI · gpt-4o           [当前使用]   │
      │ 2  Claude · claude-3-7      [专属模型]    │
      │ 3  本地 · qwen3-32b           暂不可用     │
      │ 4  DeepSeek · deepseek-v3                 │
      ├──────────────────────────────────────────┤
      │ · 回复序号切换 · 60 秒内有效 · 0 = 恢复默认 │
      └──────────────────────────────────────────┘
用户：2
bot ：已切换为：Claude · claude-3-7，从下一条消息起生效。
```

规则（都写在卡片上，也在这里备查）：

- **默认是「只读」**：等级里的开关不开，用户发 `/切换模型` **仍然能看到卡片**（自己在用什么、还有哪些候选），
  但**切不了**——回序号不生效，`/切换模型 2` 会明确回一句「只读：所在分组未开放模型切换」；
- **候选从哪来**：
  - 等级里配了「可切换模型」名单 → **只能从这份名单里挑**（外加他自己的专属模型）；
  - 没配名单 → **兜底三项**：`当前使用的模型` / `系统默认模型` / `等级备用模型`；
- 卡片会标出**当前使用的那个**（即使它不在名单里，也会被列出来标记），序号按配置顺序排，不会乱跳；
- 卡片右侧头像是**这个会话的**：群里显示**群头像**、私聊显示对方头像（本地没有会现抓一次并缓存，
  抓不到才用插件图标占位）；
- 卡片在**回复序号的有效期一到就自动撤回**（`model_switch_timeout_sec`，默认 60 秒；
  两件事共用同一个数字，不会出现"卡片先没了"或"过期了还挂着"）：它本来就是一次性交互卡，
  留着只会占地。**撤回只在 QQ 上有效**，其它平台自动变成「只发不撤」；不想要撤回可以把
  `model_card_recall` 关掉；
- 标题区那行会带**今日用量**（私聊 = 这个人、群聊 = 这个群；查不到统计时这一行才不显示）；
- **群聊里只有管理员能切**：切换改的是**这个群的专属模型**（对全群生效），
  谁都能切会把整个群搅乱。普通成员在群里发这个指令会被直接拒绝并提示私聊使用；
  **管理员不受此限制**；
- **管理员另外也不受「允许切换」开关限制**（开关关着也能切，方便排查问题）；
- **切换 = 改专属模型**（v1.3.12）：私聊切自己的专属模型、群里（管理员）切这个群的专属模型 ——
  与控制台好友 / 群详情抽屉里的「专属模型」是**同一份配置**，手动切换与指令切换互相同步；
- **优先级：专属模型 > 等级主 / 备用模型 > 系统默认**；
- 想直接切也可以：`/切换模型 2`；`/切换模型 0`（或回 `0`）= 恢复默认（清掉专属模型，跟随等级配置）；
- **私聊与群聊是两份专属模型，互不影响**；每个群各一份，在 A 群切换不影响 B 群；
- 切换成功后会回一张**回执小卡片**（只讲「现在用的是哪个」）；渲染不出来时退回文字；
- 卡片上每个候选还会带**一行小字的数据**（需要装「萌萌模型控制台」，见下一节）：
  **行底是一条「左端健康色 → 右端中性底」的渐变**（正常几乎看不出来、降级琥珀、故障红、
  无数据灰），右侧是延迟与成功率，第二行写「**这条数据是什么时候的**」——
  因为刷新它的不只是检测，**真实对话也会**（对话多的时候数字就是新的，别以为是旧数据）；
- 配置存在插件数据库里（`policy` 的 `model`），换机器会随「规则导出」一起搬；
- 关掉 `model_switch_enabled` 则整个功能静默失效（指令不再响应）。

### 7. 模型检测：/切换模型检测

先给**当前分组允许使用的模型**做一次体检（存活 / 延迟 / 成功率），然后把最新数字标在切换卡片上。

```
用户：/切换模型检测
bot ：（先回一张「检测中」卡片）
      （跑完自动再发一张「模型切换」卡片，直接回序号就能切换）
```

- **需要先安装「萌萌模型控制台」**（[astrbot_plugin_model_panel](https://github.com/windExplorer/astrbot_plugin_model_panel)）：
  检测由它执行、结果也存在它那边（它的面板上会把这次记为「**插件联动**」），本插件只负责发起与展示。
  没装时这条指令会**直接告诉你去装**，不会静默不响应。
- **默认关，且是按分组逐个开的**：在「限额 → 等级管理」里打开该等级的**「允许检测模型」**。
  它和「允许切换模型」是**两个独立开关** —— 检测会**真打模型、消耗额度**，
  「能看」不等于「愿意花钱测」；**管理员不受这个开关限制**（排查用）。
- **两道冷却**，都在配置页的「模型检测」分区：
  - `detect_command_cooldown_min`（默认 **30** 分钟）：**同一个人**两次检测的最小间隔，**管理员豁免**；
  - `detect_model_cooldown_min`（默认 **5** 分钟）：**同一个模型**两次检测的最小间隔，
    跨用户 / 跨群 / 重启后都有效（依据是模型控制台记的「上次探测时间」）。
    冷却期内的模型会被**跳过**并在卡片上注明，而不是排队等 —— 排队等来的数字已经过期了。
- `detect_max_models`（默认 **8**）：单次最多检测几个；分组里模型更多时只测前面的。
- 检测**全部跑完才发结果卡**，期间先回一张「检测中」提示卡（N 个模型串起来最坏要等 N × 超时，
  同步等会让人以为 bot 挂了）；结果卡发出来后**直接回序号就能切换**，不用再发一次 `/切换模型`。
- 和模型控制台的手动 / 定时检测**共用同一把锁**：撞车时（对方已有检测在跑）会告诉你稍后再试，
  不会排队也不会重复打一遍。
- 关掉 `detect_command_enabled` 则整条指令静默失效。

### 8. 备份与迁移

「配置 → 备份与迁移」：导出全部规则（权限 · 等级 · 归级 · 额度）为 JSON，
换机器导入即可——等级按名字重建并自动修正归级 / 额度引用；用量与日志不随迁。

## 控制台页面

| 页面 | 内容 |
| --- | --- |
| 总览 | 指标卡 + 用量趋势（今日视图按小时）+ 模型占比 / 拒绝原因分布 + 用量 Top 对象 |
| 统计 | 用量明细（筛选 / 分页 / CSV 导出）+ 最常触发 / 最常被拦指令 Top10 + 活跃时段热力图 + 操作审计 |
| 私聊 | 好友列表（默认按最近回复倒序；可切私聊 / 群聊场景；关键词 / 权限 / 等级筛选）+ 批量权限与归级 |
| 群聊 | 群列表（筛选排序同私聊）+ 批量操作 + 每行「成员」进入群成员级管控 |
| 限额 | 全局默认额度 + 等级管理（额度模板 / 模型路由）+ 对象专属额度 |
| 指令 | 指令清单 + 每条指令的全局策略与例外规则 + 对象体检 |
| 配置 | 运行信息 + 全部配置项 + 备份与迁移 |

## 配置项

全部配置在控制台「配置」页（或 AstrBot 插件配置页）可改，每项都带说明。重点项：

| 配置 | 说明 |
| --- | --- |
| `default_effect` | LLM 的全局默认策略（`allow` 放行为主 / `deny` 白名单模式） |
| `quota_mode` | `observe` 只记账不拦（**默认，建议先跑一周**）/ `enforce` 超限拦截 |
| `admin_exempt` | 管理员豁免（默认开，避免把自己锁在外面） |
| `command_guard_enabled` / `default_command_effect` | 指令管控开关 / 指令默认策略（`deny` = 指令白名单） |
| `command_guard_priority` | 指令拦截优先级（默认 1000；拦不住就调大） |
| `model_route_enabled` | 是否启用等级模型路由 |
| `model_switch_enabled` / `model_switch_timeout_sec` | 是否允许用户自查自切模型 / 等他回序号的秒数（默认 60） |
| `model_card_theme` | 卡片配色主题：`indigo`（默认）/ `teal` / `amber` / `rose`（换的是整张卡的头/脚配色） |
| `model_card_font` | 卡片字体文件路径（留空 = 用插件自带中文字体，再退到系统字体） |
| `model_card_recall` | 卡片到期后自动撤回（默认开；时间就是上面的 `model_switch_timeout_sec`，仅 QQ 平台生效） |
| `detect_command_enabled` | 是否允许用户用 `/切换模型检测`（默认开；**能不能用还要看各等级的「允许检测模型」**，那个默认关） |
| `detect_command_cooldown_min` / `detect_model_cooldown_min` | 指令冷却（默认 30 分钟，**仅非管理员**）/ 同一模型重复检测间隔（默认 5 分钟） |
| `detect_max_models` | 单次最多检测几个模型（默认 8；每个模型都会真打一次，所以有硬上限） |
| `sync_group_members` | 自动同步时是否拉取群成员（默认关；量级 = 群数 × 人数） |
| `track_bot_messages` / `track_command_usage` | 最后回复记录 / 指令触发流水（统计页数据来源） |
| `avatar_source` / `avatar_cache_days` | 头像来源与缓存天数 |
| `retention_days` | 用量明细保留天数（默认 180，`0` = 永久） |

## 常见问题

- **改了规则不生效？** 所有写操作完成后立即生效（无需重启）；改「默认策略」类配置也会热载。
- **指令拦截不住？** 调大 `command_guard_priority`——它必须比指令处理器（默认 1000）及其它抢跑插件的优先级更高。
- **升级会丢配置吗？** 不会。数据库结构自动迁移，从任意旧版本直升，规则与用量都保留。
- **换机器怎么搬？** 见上文「备份与迁移」。
- **CSV 用 Excel 打开乱码？** 文件已带 UTF-8 BOM；若 WPS / 旧版 Excel 仍异常，用「数据 → 从文本导入」选 UTF-8。
- **`/切换模型` 收到的是文字列表而不是卡片？** 说明这台机器上没找到可用的中文字体
  （也不该发一屏豆腐块）。包内自带一份中文字体，正常不会发生；真发生了就在「配置 → 模型路由」
  里把 `model_card_font` 指向一个中文字体文件（如 Windows 的 `C:\Windows\Fonts\msyh.ttc`）。
  功能不受影响——文字列表里的序号一样能回。
- **`/切换模型检测` 没反应 / 只回一句「请先安装」？** 这条指令**依赖另一个插件**
  （[萌萌模型控制台](https://github.com/windExplorer/astrbot_plugin_model_panel)）：检测与数据都在它那边，
  没装 / 被禁用 / 版本过旧时，指令会直接告诉你去装（不会静默不响应）。
  装好了还是不能用，就看两处：配置页的 `detect_command_enabled`（总开关）与
  「限额 → 等级管理」里那个等级的**「允许检测模型」**（默认关）。
- **卡片上有的行没有延迟和成功率？** 那是这个模型还没有任何记录（没被调用过、也没被测过）——
  宁可空着也不写「0ms / 100%」。发一次 `/切换模型检测` 就有了。
- **群成员列表是空的？** 在「群聊」页点该行的「同步成员」；全局自动拉取的开关 `sync_group_members` 默认关闭。
- **为什么有的好友有用量但没有「最后回复」？** 「今日用量」按人头聚合（含他在群里的消费），
  而「最后回复」只记**私聊**——bot 在群里的回复记在群名下。只在群里聊过的好友就是这种状态。
- **为什么有的记录延迟是空的？** 指令流水没有延迟概念（显示 `-`）；LLM 行偶尔空白属于边缘情况（并发 / 清理窗口），不影响额度。
- **统计和管控覆盖所有 AI 消耗吗？** 覆盖**消息对话**（用户发消息 → bot 回复）的全部链路。
  但如果某个插件**绕过消息管线直接调用模型接口**（典型的如定时 AI 播报、会话总结类插件），
  那部分消耗不经过本插件的钩子——**不计入统计、不扣额度、也不受权限管控**。
  这是 AstrBot 插件钩子体系的限制，遇到这类插件请知悉。
