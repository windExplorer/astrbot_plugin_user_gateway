M6：统计页（明细 / 指令维度 / 审计 / 导出）（v0.7.0）

背景
- 后端的 /usage（明细）与 /audit（审计）从 M0 就在，但前端一直没有页面用它们；
  PRD §4.4 要求的「明细 + CSV 导出」与 M3 追加的「指令 Top 榜 + 时段热力图」一直空着。

新增
- 统计页（#/stats）：
  · 用量明细：区间 / 类型（LLM / 指令）/ 状态 / 对象 / 发起人筛选 + 分页 + token 分项；
  · CSV 导出：后端生成（带 UTF-8 BOM，Excel 不乱码），前端 Blob 落地；
    沙箱可能拦下载，所以同时弹窗展示内容供复制；
  · 最常触发 / 最常被拦的指令 Top10；
  · LLM 活跃时段热力图（24 小时 × 星期，按本地时间分桶）；
  · 操作审计（谁在什么时候改了什么规则）。
- 指令触发流水：新配置 track_command_usage（默认开），成功执行的指令也记一条
  kind='command' 流水，用于「最常触发的指令」；与 LLM 口径完全分开（calls/token 只统计
  kind='llm'，已加自检固定这一点）。
- 后端：store.top_commands() / hour_heatmap() / export_usage_csv()；新接口
  /stats/commands、/usage/export。
- 私聊 / 群聊页支持按指令权限过滤；两页顶部新增「权限怎么算」说明卡，
  讲清「继承 / 放行 / 禁止」是互斥三态、以及 LLM 与指令是两套独立规则。

修正
- 「指令」页说明还写着「指令权限不参与等级档位」（M5 后已不成立），改正为
  「等级只管整体能不能用指令，且压得住单条指令的放行」。
- 群聊页挂着「群成员级管控将在 M3 上线」的过时标签（该功能实际未实现），移除；
  README 里从「M3 已完成」改为「待办」，避免文档撒谎。

自检
- tests/test_store.py 新增 [5.1]：指令 Top 榜（含排序）、热力图分桶、CSV
  （BOM / 表头 / 行数 / 按类型过滤）、以及「指令流水不污染 LLM 口径」。
